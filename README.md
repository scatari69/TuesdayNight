# TuesdayNight — Deadlock Discord Bot

Самостоятельный Discord-бот без Telegram-зависимостей. Состав всегда берется
из участников настроенной роли, например `@deadlock`; список игроков в JSON
не хранится. Боты в состав не включаются. Сбор, настройки и статистика изолированы
по серверам. На сервере один текущий сбор и один настроенный канал.

## Установка

1. Создай приложение и бота в [Discord Developer Portal](https://discord.com/developers/applications).
2. На странице **Bot** включи **Server Members Intent**. Message Content Intent
   не нужен: управление через slash-команды.
3. Пригласи бота со scopes `bot` и `applications.commands`. Права: View Channels,
   Send Messages, Read Message History, Add Reactions и Manage Roles. Роль бота
   должна быть выше ролей, которые он будет выдавать. Administrator не требуется.
4. Создай обычную роль `deadlock` без разрешений. Доступ к каналам можно дать
   ей через overrides канала. Для reaction roles бот принимает только роли
   без серверных разрешений, чтобы не раздавать права модераторов.
5. В этой папке скопируй `.env.example` в `.env`, заполни `DISCORD_TOKEN`.
   `DISCORD_GUILD_ID` позволяет сразу зарегистрировать команды на тестовом
   сервере; без него команды регистрируются глобально (могут появиться с задержкой).
6. Запусти:

```bash
cd ~/Projects/TuesdayNight
cp .env.example .env
# Заполни .env перед запуском.
docker compose up -d --build
```

Локальный запуск из папки `TuesdayNight`:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
# Переменные из .env автоматически читает только Docker Compose.
export DISCORD_TOKEN='токен'
export TZ=Europe/Kyiv
.venv/bin/python bot.py
```

`DATA_DIR` задает каталог состояния (по умолчанию `data`, в контейнере `/app/data`).
Том `./data` сохраняется при пересборке. JSON пишется атомарно под блокировкой;
поврежденный файл останавливает запуск, а не затирается пустыми данными.
Запускай один экземпляр на каталог данных. Данные Telegram не мигрируются:
Discord использует другие идентификаторы пользователей и серверов.

## Первичная настройка

Администратор с Manage Server выполняет:

```text
/setup role:@deadlock channel:#deadlock
/settings cooldown:60 reset_time:03:00 autotag:20:00
```

`/settings` без аргументов показывает настройки. `autotag:disable` отключает
автосбор. Время — по `TZ` процесса; по умолчанию контейнер использует Europe/Kyiv.
Планировщик работает, пока бот запущен: пропущенные за время простоя события
не догоняет. Ночной сброс и `/clear` закрывают старые кнопки.

## Роли по реакциям

Пользователь с Manage Roles:

1. `/reactionrole panel channel:#roles text:Поставь 🎮, чтобы получить роль Deadlock`.
2. Скопируй ID созданного сообщения из ответа.
3. `/reactionrole add channel:#roles message_id:123456789 emoji:🎮 role:@deadlock`.

Теперь реакция 🎮 выдает `@deadlock`, снятие реакции удаляет роль. Можно добавить
несколько разных пар эмодзи/роль на одно сообщение. Поддерживаются Unicode
и custom emoji в формате `<:name:id>` / `<a:name:id>`. Роль должна быть ниже
старшей роли бота и настраивающего пользователя (кроме администратора).

- `/reactionrole list` — привязки сервера.
- `/reactionrole remove message_id:... emoji:🎮` — убрать привязку.
- Привязки сохраняются после перезапуска и не зависят от кэша сообщений.
- Привязывать роли можно только к сообщениям этого бота.
- Удаление привязки или сообщения сохраняет уже выданные роли.
- Снятие реакции удаляет роль даже если она была выдана вручную. Не используй
  одну роль одновременно в нескольких панелях: снятие любой реакции ее удалит.
- Реакции, добавленные до настройки привязки или пока бот был выключен,
  автоматически не сверяются: пользователь должен снять и поставить реакцию
  заново. Очистка всех реакций модератором также не отзывает выданные роли.

## Команды

| Команда | Действие |
| --- | --- |
| `/tag` | Участник роли зовет тех, кто еще не нажал «Играю», с кулдауном |
| `/team` | Текущие участники роли |
| `/me` | Личная статистика и Deadlock-профиль |
| `/link profile:...` | Steam/tracklock/числовой ID; `remove` отвязывает |
| `/stats` | Число сборов, топ-3 тегавших, напулявших и отказов |
| `/clear` | Закрыть сбор и снять кулдаун; Manage Server |
| `/setup` | Роль и канал; Manage Server |
| `/settings` | Кулдаун и расписание; Manage Server |
| `/cleanup` | Удалить сообщения этого бота за сутки в текущем канале; Manage Messages |
| `/reactionrole ...` | Панели, привязки и их просмотр; Manage Roles |

Кнопки «Играю»/«Не играю» работают после перезапуска; голосовать могут только
текущие участники роли. Повторное нажатие не увеличивает счетчик отказов.
Новый `/tag` продолжает текущий сбор; все его сообщения используют общие голоса,
при голосовании обновляется нажатое сообщение. Последние 100 сообщений сбора
принимают голоса. Смена роли через `/setup` закрывает старые сборы.
`/tag` от постороннего увеличивает личный счетчик «напулов», не пингуя игроков.

`/cleanup` удаляет в том числе панели reaction roles в выбранном канале.
Для панелей используй отдельный канал, который не очищаешь этой командой.

Steam-статистика использует API Deadlock: последние 30 матчей, ранг и любимый
герой. `STEAM_API_KEY` нужен только для vanity-ссылок `steamcommunity.com/id/...`.
История матчей кэшируется на 15 минут; ранги — на час. Недоступность API
не мешает обычным сборам. Ранги показаны в `/me`, в списке сбора — имена игроков.
Вывод больших списков ограничен размером Discord-сообщения.

## Проверки

Из корня репозитория, с установленными Discord-зависимостями:

```bash
python -m unittest discover -s . -v
```

Тесты не подключаются к Discord и не используют рабочие данные. Они проверяют
сохранение, изоляцию серверов, конкурентные голоса, текущий состав роли,
кулдаун, закрытые сборы, реакционные роли и регистрацию slash-команд.

Документация библиотеки: [intents](https://discordpy.readthedocs.io/en/stable/intents.html),
[raw reaction events](https://discordpy.readthedocs.io/en/stable/api.html#discord.on_raw_reaction_add),
[persistent views](https://github.com/Rapptz/discord.py/blob/master/examples/views/persistent.py).
