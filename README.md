# TuesdayNight

Самостоятельный Discord-бот для игровых сборов Deadlock и гильдии WoW Retail.
Команды, кнопки и ответы бота — на английском языке.

## Возможности

- **Сборы игроков:** приглашения через `/tag`, кнопки участия и отказа,
  автоматические сборы по расписанию, сброс голосов и статистика. Состав берётся
  из текущих участников настроенной Discord-роли, без ботов.
- **Deadlock:** привязка Steam-профиля через `/link`, ранг и статистика последних
  30 матчей через `/me`.
- **Роли по реакциям:** выдача и снятие ролей через панели `/reactionrole`.
  Поддерживаются обычные и серверные эмодзи; роли с серверными разрешениями,
  управляемые роли и `@everyone` запрещены.
- **WoW-дашборд:** рейдовый прогресс, места гильдии на сервере, топ-10 персонажей
  по экипированному ilvl и рейтингу Mythic+. Данные Raider.IO обновляются
  автоматически каждые 30 минут с учётом кэша; при сбое сохраняется последний результат.
- **Персонажи WoW:** подтверждение владения через Battle.net, привязка нескольких
  персонажей и выбор основного через `/character`.
- **Группы Mythic+:** режимы Learning и Push, состав 1 танк / 1 лекарь / 3 DPS,
  проверка рейтинга, экипировки и опыта выбранного персонажа. Есть очередь,
  подтверждение освободившегося места, одобрение исключений лидером и повторная
  проверка состава перед стартом.

Настройки и данные разделены по Discord-серверам. Кнопки сборов и Mythic+
работают после перезапуска. Обычные ответы не пингуют роли и `@everyone`;
приглашения на сбор и предложения места в очереди упоминают конкретных участников.

## Запуск через Docker

Нужны Docker с Compose и токен Discord-бота.

### 1. Настройка Discord

В [Discord Developer Portal](https://discord.com/developers/applications)
создайте приложение с ботом и включите **Server Members Intent**.
Message Content Intent не нужен.

Пригласите бота со scopes `bot` и `applications.commands`. Выдайте права
**View Channels**, **Send Messages**, **Read Message History**, **Embed Links**,
**Add Reactions** и **Manage Roles**. Роль бота должна находиться выше выдаваемых
ролей. Права Administrator не требуются; дашборд можно закрепить вручную.

### 2. Конфигурация и запуск

```bash
git clone https://github.com/scatari69/TuesdayNight.git
cd TuesdayNight
cp .env.example .env
```

Заполните `.env`:

| Переменная | Назначение |
| --- | --- |
| `DISCORD_TOKEN` | Обязательный токен бота |
| `DISCORD_GUILD_ID` | Необязательно: ID сервера для быстрой регистрации команд; без него команды глобальные |
| `TZ` | Часовой пояс расписания, по умолчанию `Europe/Kyiv` |
| `STEAM_API_KEY` | Только для ссылок вида `steamcommunity.com/id/...` |
| `BNET_CLIENT_ID`, `BNET_CLIENT_SECRET`, `BNET_REDIRECT_URI` | Для привязки WoW-персонажей; настройка ниже |

```bash
docker compose up -d --build
docker compose logs -f
```

Состояние хранится в `./data/state.json`, подключённом в контейнер как
`/app/data`, и переживает пересоздание контейнера. Сохраняйте резервную копию
`./data`; запускайте только один экземпляр бота на этот каталог.
Не публикуйте `.env` и пользовательские данные.

Обновление и остановка:

```bash
git pull
docker compose up -d --build
# Остановить бота:
docker compose down
```

### 3. Первичная настройка

Для сборов участник с правом **Manage Server** задаёт роль и канал:

```text
/setup role:@deadlock channel:#gatherings
/settings cooldown:60 reset_time:03:00 autotag:20:00
```

`cooldown` задаётся в секундах, время — в часовом поясе `TZ`.
`autotag:disable` отключает автосборы. Пропущенные во время отключения события
не воспроизводятся. Игроки используют `/tag`, `/team`, `/me`, `/link` и `/stats`;
администраторы — `/clear` для закрытия сбора и `/cleanup` для удаления сообщений
бота за последние сутки в текущем канале. `/cleanup` удаляет и панели ролей,
поэтому размещайте их в отдельном канале.

Для ролей по реакциям участник с правом **Manage Roles** создаёт панель,
затем использует ID сообщения из ответа:

```text
/reactionrole panel channel:#roles text:Нажмите 🎮 для получения роли
/reactionrole add channel:#roles message_id:ID_СООБЩЕНИЯ emoji:🎮 role:@deadlock
```

Список и удаление привязок — `/reactionrole list` и `/reactionrole remove`.
Снятие реакции снимает роль, даже если она была выдана вручную. Удаление самой
привязки оставляет выданные роли. Реакции, поставленные во время отключения бота,
автоматически не обрабатываются.

WoW-дашборд настраивается отдельно и не требует ключей API или Battle.net:

```text
/dashboard setup region:eu realm:tarren-mill guild_name:Название channel:#guild-dashboard
```

Укажите свои регион, сервер и гильдию. `/dashboard refresh` запрашивает обновление
с учётом кэша, `/dashboard status` показывает состояние и последнюю ошибку.
Данные Raider.IO могут быть неполными или запаздывать.

### 4. Battle.net и Mythic+ — при необходимости

Создайте приложение в [Battle.net Developer Portal](https://develop.battle.net/access/clients)
и зарегистрируйте HTTPS-адрес возврата. Заполните все три переменные в `.env`:

```dotenv
BNET_CLIENT_ID=your-client-id
BNET_CLIENT_SECRET=your-client-secret
BNET_REDIRECT_URI=https://bot.example.com/oauth/battlenet/callback
```

Адрес должен точно совпадать с зарегистрированным, иметь путь
`/oauth/battlenet/callback` и не содержать query-параметров или фрагмента.
Настройте домен и HTTPS reverse proxy на `127.0.0.1:8080`, куда Compose публикует
callback. Например, для Caddy на хосте:

```caddyfile
bot.example.com {
    handle /oauth/battlenet/callback {
        reverse_proxy 127.0.0.1:8080
    }
    respond "Not found" 404
}
```

Не записывайте query-параметры callback в логи прокси: они содержат одноразовый
код авторизации. Если прокси работает в контейнере, направьте его на порт `8080`
бота в общей приватной сети. Пересоздайте контейнер командой
`docker compose up -d --build`.

Игрок выполняет `/character link region:eu`, входит в Battle.net с разрешением
`wow.profile`, затем выбирает персонажей через `/character add`.
Ссылка входа и последующий выбор действуют по 10 минут. Управление привязками:
`/character list`, `/character main`, `/character remove`, `/character unlink`.
OAuth-токены не сохраняются. Без этой функции оставьте все три `BNET_*`
переменные из примера пустыми.

Для Mythic+ администратор выполняет `/mplus setup`, указывая канал и
`expansion_id` нужного дополнения из Raider.IO. Сезон и подземелья бот определяет
через API. Для Push нужно задать требования через `/mplus rule`;
Learning по умолчанию не требует минимального рейтинга, ilvl и опыта.
Текущие требования показывает `/mplus rules`.

Игрок создаёт группу через `/mplus create`: выбирает подземелье, уровень ключа,
привязанного персонажа, роль, режим и время в формате `2026-10-25T20:00+02:00`
со своей будущей датой и часовым смещением, в пределах 30 дней.
Участники записываются кнопкой на карточке или через `/mplus join`.
Если настроена роль игроков через `/setup`, она нужна и для участия в Mythic+
(кроме участников с Manage Server).

`/mplus show` показывает группу, `/mplus leave` выходит из неё. Лидер или
участник с Manage Server управляет группой через `/mplus approve`, `/mplus kick`,
`/mplus transfer`, `/mplus start` и `/mplus cancel`.
Выход лидера отменяет группу; для сохранения сначала передайте лидерство.
Старт требует подтверждённого состава 1/1/3 и только закрывает запись в Discord.

## Архитектура

Python 3.11+, `discord.py` 2.x, один асинхронный процесс без внешней базы данных.

| Файл | Ответственность |
| --- | --- |
| `bot.py` | Discord-клиент, регистрация команд, сборы, постоянные кнопки, роли по реакциям и фоновые задачи |
| `state.py` | JSON-хранилище по ID сервера: чтение через `Store.read`, изменения через `Store.edit`, блокировка и атомарная запись с откатом при ошибках |
| `deadlock.py` | Steam/Deadlock API, разрешение ссылок на профили, статистика и кэши |
| `wow.py` | Общий клиент Raider.IO: таймауты, ограничение частоты, кэш, снимок гильдии и оформление дашборда |
| `bnet.py` | Battle.net OAuth, HTTP-callback на порту 8080, проверка владения и привязка персонажей |
| `mplus.py` | Команды и карточки Mythic+, проверка допуска, очередь и управление группами |
| `test_*.py` | Unit-тесты с подменой Discord и HTTP, без рабочего состояния и реальных подключений |
| `Dockerfile`, `docker-compose.yaml` | Сборка контейнера, переменные окружения, каталог данных и порт callback |

В JSON сохраняются настройки, голоса, статистика, привязки ролей и персонажей,
последний снимок дашборда и группы Mythic+. Состав Discord-роли читается из
Discord, полный состав WoW-гильдии на диск не записывается.
HTTP-клиенты используют таймауты и закрываются вместе с ботом.

Запуск тестов из корня проекта с установленными зависимостями:

```bash
python -m unittest discover -s . -v
```
